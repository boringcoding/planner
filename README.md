# planner

Планировка жилого дома 8,0 × 12,5 м на участке 19 × 35 м.
Цоколь + первый этаж с гаражом + второй этаж.

## Идея

Геометрия живёт в одном файле `data/house.json` — в миллиметрах, целыми числами.
Всё остальное из него выводится: чертежи, экспликации, площади, проверки.
Площади нигде не хранятся, а считаются — подписать одно, а нарисовать другое невозможно.

Геометрия подписей тоже считается в одном месте — в `render.mjs` — и оттуда же
её берут правила. Пока рамки текста считались бы отдельно от отрисовки, они
разошлись бы, и наложения проскакивали бы мимо проверки.

У каждой стены, помещения, проёма, окна и предмета есть идентификатор вида
`second.f12` — уровень, тип, номер. Он присваивается один раз и при перестановке
в массиве не меняется: развёртки по электрике, воде и вентиляции будут ссылаться
на розетку у стены `second.w3` и на щит `cokol.f9`, а не на «стену слева от окна».

Высоты — такие же данные, как план: `clear` у уровня, `hz` у проёма и предмета,
`sill` и `hz` у окна. Отдельного признака «высокий шкаф» нет, он выводится из
высоты; поэтому машина под окном гаража с подоконником 1500 свет не отнимает,
а холодильник под окном кухни — отнимает.

## Разделы

Планы уровней — только часть. Электрика, вода, отопление, вентиляция
и слаботочка живут в `data/systems.json` как точки: помещение, грань,
расстояние по грани, отметка, вид. Точка — решение, поэтому она хранится.

Трасса — не решение, а следствие, поэтому она считается: от источника до
этажного узла по стояку, дальше шлейфом или лучом до точки, ломаной строго
по осям и через проёмы. Отсюда метраж каждой линии, ведомость по материалам
и общий итог — они пересчитываются при любой правке плана, включая перенос
стены. Топология взята та, по которой дом собирают: звезда от щита к каждой
розетке дала бы 1800 м кабеля, а это число хуже отсутствующего.

Развёртка помещения — лента из четырёх граней подряд, с проёмами, мебелью
и точками всех разделов сразу: она и нужна затем, чтобы розетка не оказалась
там же, где вытяжка, а радиатор — за кухонным фронтом. Последнее нашлось
именно так и стало правилом.

## Выгрузка и модель

`npm run ifc` пишет `out/house.ifc` — IFC4, единицы миллиметры: помещения,
стены, проёмы с заполнениями, перекрытия, лестница, мебель и точки всех
разделов, собранные в четыре системы. Идентификаторы вида `second.f12`
уходят в свойства элементов, поэтому дорога обратно не теряется.

Файл собирается руками, как и всё остальное: IFC текстовый, геометрия у нас
коробочная, библиотека не нужна. Две ловушки, на которые стоит смотреть при
правках: план нарисован в экранных координатах (X вправо, Y вниз), а IFC
правый и Z вверх — Y приходится отражать, иначе дом приезжает зеркальным
и это не бросается в глаза; и кириллица в STEP кодируется `\X2\...\X0\`,
иначе имена помещений превращаются в кашу.

Выгрузка проверяет сама себя: разбирает собственный файл и требует, чтобы
все ссылки разрешались, идентификаторы не повторялись, а количества совпали
с моделью — проёмы вырезаны из стен и перекрытий, заполнения стоят в проёмах.
Отдельно сверяется место каждого проёма: экспорт кладёт его в осях стены,
проверка разворачивает цепочку `IfcLocalPlacement` обратно в мир и сравнивает
с планом. Так нашлись семь зеркальных проёмов восточной стены — считать
координату дважды и разными путями стоит именно ради этого.

Внешняя проверка — `ifcopenshell.validate(..., express_rules=True)`: сейчас
ноль замечаний. Она ловит то, чего не видит своя: например, что ось и
направление в `IfcAxis2Placement3D` задаются вместе или не задаются вовсе.

На странице тот же файл читает `web-ifc` — движок IFC.js — и рисуется
на WebGL2 со слоями по разделам и уровням. Это не вторая отрисовка наших
данных: если модель собралась в браузере, значит в файле лежит то,
что мы думаем.

## Команды

```
npm run check   # прогон правил: нормы и эргономика
npm run selftest # проверка проверок: каждое правило ломают нарочно
npm run build   # out/*.svg
npm run guard   # сравнение с out/*.svg: правка не должна была менять чертёж
npm run shot    # out/*.png  (нужен @resvg/resvg-js, ставится через npm i)
npm run points  # первичная расстановка точек раздела (пишет data/systems.json)
npm run ifc     # out/house.ifc + проверка выгрузки
npm run site    # site/ — страница: планы, разделы, ведомости, развёртки, задание
npm run all
```

`check` возвращает ненулевой код при любом нарушении — годится для CI и для pre-commit.
`selftest` держит правила честными: каждое из них ломает геометрию по-своему
и требует, чтобы нарушение было найдено. Правило, которое ничего не ловит,
хуже отсутствующего — оно создаёт ощущение проверенности.

## Публикация

`.github/workflows/pages.yml` на каждый push прогоняет `check` и `selftest`, собирает `site/`
и выкладывает на GitHub Pages. Правила стоят воротами: с нарушением геометрии
страница не обновится.

Один шаг делается руками, токен workflow на это прав не имеет:
Settings → Pages → Source → **GitHub Actions**. После этого достаточно
перезапустить последний workflow — деплой пройдёт.

Адреса и данные владельца в репозитории нет и быть не должно: он публичный,
и с него собирается сайт. Площадка описана только числами — климат, сейсмика,
габарит участка, ориентация.

## Структура

```
data/house.json   геометрия: оболочка, уровни, стены, проёмы, окна, помещения, мебель
data/brief.json   задание: что зафиксировано, ограничения площадки
data/systems.json точки разделов: ЭОМ, ВК, ОВ, СС
src/model.mjs     грани помещений, граф проёмов, ортогональные пути
src/render.mjs    отрисовка плана и планов по разделам в SVG
src/elev.mjs      развёртки помещений
src/systems.mjs   трассы и ведомости: магистрали, шлейфы, лучи, метражи
src/ifc.mjs       выгрузка в IFC4
src/viewer.js     смотрелка IFC на странице: web-ifc + WebGL2
src/rules.mjs     правила плана: связность, зоны подхода, проходы, окна, лестница, стояк, подписи
src/sysrules.mjs  правила разделов: посадка точек, высоты, зоны, полнота программы
bin/check.mjs     прогон правил
bin/selftest.mjs  ломает данные нарочно и требует, чтобы правило сработало
bin/build.mjs     сборка SVG
bin/guard.mjs     страховка на время перестройки модели: чертёж не изменился
bin/genpoints.mjs первичная расстановка точек по программе помещений
bin/ifc.mjs       выгрузка в IFC и проверка того, что выгрузилось
bin/shot.mjs      растеризация в PNG
bin/site.mjs      сборка страницы для Pages
```

## Система координат

X — поперёк дома (0 … 8000), Y — вдоль, от улицы вглубь участка (0 … 12500).
Верх плана — юго-запад, там улица и ворота. Азимут фронта 235°.
Низ плана — северо-восток, глубина участка. Правая сторона — юго-восток, солнечная.
