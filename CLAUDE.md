# Как работать с этим репозиторием

## Главное правило

**Не отдавать результат, не посмотрев на него глазами.**

Цикл на каждую правку геометрии:

```
правка data/house.json  ->  npm run check  ->  npm run build && npm run shot  ->  посмотреть out/*.png  ->  починить
                                            ->  npm run site   ->  открыть site/index.html
```

Список координат и картинка — это разные вещи. Ванна вплотную к дверному
проёму в JSON выглядит нормально и мгновенно видна на рендере.
Прогонять цикл до чистого результата, и только потом показывать человеку.

## Второе правило

Каждый найденный дефект превращается в правило в `src/rules.mjs`,
а не в исправление одной координаты. Иначе он вернётся через две итерации.

Правило, которое ничего не ловит, хуже отсутствующего: оно создаёт ощущение
проверенности. Написав правило, сломай данные нарочно и убедись, что оно сработало.

## Перестройка модели

Впереди развёртки по электрике, воде, отоплению и слаботочке. Они ссылаются на
элементы плана, поэтому у стен, помещений, проёмов, окон и предметов появились
идентификаторы `<уровень>.<тип><номер>` и высоты (`clear`, `hz`, `sill`).
Идентификатор присваивается один раз: при добавлении элемента берётся следующий
свободный номер, а не пересчёт массива. Правило требует, чтобы он был и не
повторялся.

Правка, которая перекладывает данные, но не должна менять чертёж, проверяется
байтами:

```
npm run build   # эталон в out/
... правка ...
npm run guard   # разошлось — значит, задело геометрию
```

Прямоугольник помещения на чертеже не рисуется — виден только контур стен.
Поэтому помещение и стены сверяются отдельным правилом: вместе они обязаны
покрыть внутренний габарит без зазоров и без наложений. Глазами такой дефект
не ловится.

Второе такое место — проходимость. Попарные зазоры между предметами меряются
давно, но каждый зазор по отдельности может быть шире нормы, а вместе они
образуют два кармана без связи между собой. Поэтому свободный пол помещения
заливается телом 550 мм по клеткам 50 мм, и от каждого проёма до каждого
предмета обязан существовать путь. Так нашлась вентшахта, вставшая поперёк
коридора второго этажа.

## Разделы

Точка раздела хранится, трасса считается. Если хочется подвинуть розетку —
правится `data/systems.json`; если хочется поменять способ прокладки —
правится `src/systems.mjs`, и метражи пересчитываются сами.

`bin/genpoints.mjs` — не сборка, а первичная расстановка: он пишет
`data/systems.json` с нуля по программе помещений и затирает ручные правки.
Запускать его после того, как точки поправлены руками, значит потерять правки.

Развёртка показывает то, чего не видно на плане: на плане радиатор под окном
и кухонный фронт вдоль той же стены — две независимые линии, а на развёртке
они в одном прямоугольнике. Так нашлось «отопление шкафа», и так же нашлись
четырнадцать розеток и вводов, стоявших за радиаторами: на плане они рядом
с прибором и не совпадают с ним ни одной координатой. Отсюда порядок в
`bin/genpoints.mjs` — радиаторы считаются раньше розеток, и всё, что ниже
800, их обходит; отсюда же правило «стоит за радиатором».

Сначала посмотреть развёртку, потом верить плану.

Подписи развёртки раскладываются той же функцией, по которой лист рисуется:
метка раздела стоит на своей отметке, подпись предмета уходит от неё вверх.
Не нашла места за шесть шагов — правило скажет, что листу тесно, вместо того
чтобы молча положить «700 · низ 1500» поверх «ВЫ».

## Выгрузка в IFC

Правка геометрии проверяется ещё и выгрузкой: `npm run ifc` разбирает
собственный файл и сверяет количества с моделью. Молча разойтись они не могут.

Два места, где легко ошибиться и долго искать. Первое: план в экранных
координатах, Y вниз; в IFC система правая, поэтому Y отражается. Забыть —
получить зеркальный дом, в котором всё на месте, но левое стало правым.
Второе: кириллица в STEP пишется как `\X2\0421...\X0\`.

Смотрелка на странице намеренно читает файл движком web-ifc, а не рисует
наши же данные второй раз: смысл в том, чтобы видеть выгрузку, а не её
обещание. Движок ставится как devDependency и раздаётся рядом со страницей;
нет движка — страница собирается без 3D, но собирается.

Место проёма считается дважды и разными путями — в экспорте по оси стены,
в проверке разворотом цепочки размещений обратно в мир. Именно так нашлись
семь зеркальных проёмов: отражение Y переворачивает ось стены, а формула
на каждую сторону света об этом не знала. Формул больше нет — смещение
проецируется на ось стены, одинаково для всех сторон и для внутренних стен.

## Модель проверяется после сборки, а не вместо неё

`npm run ifc` разбирает собственный текст: сходятся ссылки, количества, места
проёмов, отметки скатов. Этого мало. Файл может быть безупречен по составу
и пуст на экране — так и вышло: скаты лежали в нём двумя `IfcSlab`, аккуратно
посаженными под уклон, отметки сверялись, количества сходились, а на странице
крыши не было ни разу. Часть сборки не входит в пространственную структуру
(по IFC она принадлежит сборке), смотрелка искала этаж только по прямому
вхождению, не находила и клала скаты на несуществующий уровень 0, который
фильтр уровней гасит всегда.

Ни одна проверка по тексту такого не увидит. Поэтому:

```
npm run model    # открывает out/house.ifc движком web-ifc и меряет геометрию
npm run screen   # поднимает site/, открывает Chromium, снимает out/viewer.png
npm run deploy   # site + model + screen: собрать и посмотреть
```

`bin/model.mjs` спрашивает у модели то, что видит глаз: есть ли треугольники
в каждом слое, доходит ли верх до конька, приходит ли скат низом в карниз,
накрывают ли скаты контур кровли, у всех ли элементов есть тело — и главное,
не осталось ли геометрии, которую смотрелка по своим же правилам никому
не покажет. Раскладка по слоям и уровням считается там второй раз намеренно:
разойдись она со смотрелкой — и проверка перестанет отвечать на вопрос
«а видно ли это на экране». Файл в `site/` сверяется с проверенным побайтно.

У смотрелки есть инструменты, и они — состояние вида, а не классификация:
клик по элементу называет его (номер сущности лежит атрибутом в каждой
вершине, выбор — цветовой проход), alt-клик по фишке слоя оставляет только
его, срез режет дом по высоте клип-боксом в шейдере, список помещений
изолирует одно тем же клип-боксом, «оболочка 40%» делает стены, перекрытия
и кровлю полупрозрачными — так видно трассы.

Камера не только вращается. Орбиты вокруг одной точки хватало, пока смотреть
было не на что, кроме дома посреди участка; времянка в дальнем углу уезжает
за край экрана, и приблизить её нечем — зум идёт к середине. Поэтому правая
кнопка (или Shift с левой, или два пальца) сдвигает вид, а двойной клик
по элементу переносит на него точку вращения: дальше поворот и зум идут
вокруг него. Двигается не камера, а `centre` — та точка, вокруг которой она
стоит; тогда все прежние жесты продолжают работать относительно того,
на что смотришь. Пресеты фасадов после этого только разворачивают камеру
и не трогают приближение — иначе подъехать к времянке и обойти её
по сторонам света было бы нельзя. Возврат — фишка «сброс» или двойной
клик мимо модели. На телефоне те же жесты пальцами: один — поворот, два —
сдвиг и приближение разом, двойной тап — точка вращения; строка подсказки
выбирается по `(pointer: coarse)`, потому что рассказ про правую кнопку
и колесо на телефоне не подсказка, а тупик. Холсту нужен `touch-action: none`,
иначе браузер забирает жесты себе и до страницы не доходит ни одно
pointer-событие. Сдвиг на пиксель считается от расстояния и угла зрения,
а не подобран константой: иначе вблизи модель улетает от одного движения,
а издалека не сдвигается вовсе. Пресеты камеры — четыре фасада,
план, изометрия; npm run screen снимает юго-западный и северо-восточный
фасады и «оболочку» отдельными кадрами: симметрию окон и трассы видно только
с них. «Прогулка» ведёт камеру со входа через все помещения на высоте глаз
и со скоростью шага: маршрут не расставлен руками, а считается в src/tour.mjs —
граф помещений по проёмам, обход в глубину от входной двери, внутри помещения
путь по той же решётке телом 550, что и правило проходимости, лестница по
маршам. site/tour.json пишется в мировых координатах модели (Y отражён, как
вся выгрузка). Правило 41 требует, чтобы маршрут прошёл все помещения без
исключения; npm run screen снимает кадр из прогулки. Новый слой или перенос по метке правится парой: src/viewer.js
и bin/model.mjs, иначе проверка «видно ли это на экране» перестаёт отвечать
на свой вопрос.

Осторожно с осями: движок отдаёт метры и правую систему с Y вверх. Модель
у нас в миллиметрах и Z вверх. Забыть — сравнивать конёк с длиной дома
и не понимать, почему «верх модели 500».

Сторонний валидатор ставится одной командой и не хранится в репозитории:

```
pip install ifcopenshell
python3 -c "import ifcopenshell,ifcopenshell.validate as V; V.validate(ifcopenshell.open('out/house.ifc'), None, express_rules=True)"
```

Скат кровли посажен наклонной осью, а не положен плашмя с уклоном в свойствах.
Проверка разворачивает посадку обратно в мир и требует, чтобы верхний край
оказался на коньке, а нижний — на карнизе. Перевёрнутая нормаль даёт ту же
отметку в середине, ту же площадь и то же число сущностей — а дом с ложбиной
вместо конька. Иначе это не ловится ничем.

Дверь в выгрузке — коробка с полотном, окно — рама со стеклопакетом, а не
цельный блок на всю толщину стены. Первая версия отдавала блоки, и ArchiCAD
честно показывал блоки: он рисует то, что дали, а не то, что имелось в виду.
К геометрии прилагаются IfcDoorType/IfcWindowType с Lining и Panel — по ним
ArchiCAD пересобирает дверь в свой параметрический объект, — стили поверхностей
(стекло с Transparency 0.65), материалы и Pset_DoorCommon с IsExternal.
bin/ifc.mjs требует тип у каждого заполнения и прозрачное стекло в файле:
серые глыбы уже приезжали.

Трассы разделов — тоже тела: сегменты по классам (кабельный канал, труба,
воздуховод) собраны из тех же прогонов, что дали метраж в ведомости.
Второй прокладки «для картинки» нет, и правило 10а в src/sysrules.mjs требует,
чтобы сумма осевых отрезков, помноженная на жилы и запас, дала длину прогона.
Сегменты входят в IfcSystem своего раздела, поэтому смотрелка и ArchiCAD
раскладывают их по системам сами.

Чего в выгрузке нет и не появится само: состава стен по слоям, фундамента
(плита 400 в коде — заглушка, а не решение), портов у приборов.
Это не формат виноват — этого нет в данных.

Из присланной модели времянки не перенесён водосток: у архитектора это
жёлоба под обеими кромками и четыре водосточные цепи по углам свеса
(«Дух.Ш», 77 × 77, две секции по 1510). Цепь — не труба, и рисовать её
трубой значит выдумывать; в данных её нет, в смете её нет. Так же не
перенесена мебель времянки и душевой уголок из 360 алюминиевых панелей.
В кровле присланного дома нет ни одного слоя утеплителя, а остекление
кухни-гостиной 15,0 м² на 18,2 м² пола — это решения архитектора,
и правилами постоянного дома они здесь не меряются.

## Кровля, веранда, приямок

Хранится решение, а не результат: уклон, свесы, сечения, шаги — в `data/house.json`,
всё остальное считает `src/roof.mjs`. Отметки конька и карниза, площади скатов,
длина стропил, высота каждой трубы над скатом, площадь навеса, дно приямка —
вычисляются. Поменяли уклон в данных — пересчитались лист кровли, выгрузка,
смета и правила. Числа в этих четырёх местах разойтись не могут, потому что
источник у них один.

Отметка кровли — не «верх стены». Первая версия считала скат прямо от `base`,
и конёк с карнизом выходили на 400 мм ниже настоящих: на мауэрлате лежит затяжка
200, на ней стропило 200 (по вертикали 231), сверху пирог. Само по себе это
разошлось бы только с рулеткой на площадке, но из той же плоскости считается
высота труб над кровлей — и обе трубы оказывались короткими, причём правило
это пропускало, потому что мерило от той же ошибочной отметки. Теперь плоскость
покрытия собирается по цепочке мауэрлат → затяжка → стропило → пирог, и конёк
с карнизом равны +9,212 и +6,556, а не +8,809 и +6,154.

Высота трубы над кровлей — не «полметра над коньком», а СП 7.13130: ближе 1,5 м
от конька не ниже 500 над ним, до 3 м — не ниже конька, дальше — не ниже линии
под 10° от конька, и всегда не меньше 500 над скатом. Приставные трубы стоят
у самого карниза, поэтому им приходится подниматься на 1,7 м над скатом —
это внутри предела, но это плата за место, а не бесплатное решение.

Фронтоны и фризовые пояса считаются одним профилем в roofGeom: щипцовая
стена встаёт от чердачного перекрытия до низа кровельного тела, фризовый клин
закрывает щель вдоль карнизных стен — до него между плитой и скатом была
полоса в 170 мм на всю длину дома, видимая только в 3D. Смета, выгрузка
и проверка модели берут этот профиль из одного места и разойтись не могут.
В каждом фронтоне продух R.vent — он давно нарисован на листе кровли,
и модель не имеет права расходиться с чертежом. bin/model.mjs меряет фронтоны
отдельно от конька: скаты достают до 9212 и без них, «верх модели» дыру
на торцах не ловит.

Водосток перестал быть строчкой сметы: жёлоб под кромкой обоих скатов,
трубы у стен с коленом под свесом — те же числа, что считает roofGeom.
Снегозадержатели — тела с меткой roof.snow*, отмостка — полосы blindGeom
с разрывами под приямок и крыльцо: правило про борт приямка «выше отмостки»
наконец ссылается на тело, а не на воображаемую плоскость. Ограждения — на
маршах (решение st.rail, правило требует 900) и на настиле веранды, длина
которого в смете считается с тех же отрезков, что выгружаются.

Схема висячая: ферма с затяжкой на каждую стропильную пару, затяжка она же
балка чердачного перекрытия. Конькового прогона нет и быть не может — под
линией конька несущей стены нет на всю длину дома, над спальней хозяев её нет
вовсе, и стойка прогона встала бы на перекрытие. В данных прогон и стойки
какое-то время лежали, и смета за них платила; правило теперь требует стену
под коньком от торца до торца, если прогон в данных появится снова.

Плана кровли раньше не было, и это не мелочь: на планах этажей кровли нет
по определению, а вместе с ней не видно ни водостока, ни высот труб, ни того,
что навес веранды подходит под карнизный свес. Лист собирается той же функцией,
что и планы этажей, и его подписи проверяются тем же правилом на наложение.

Уклон 30° — снеговой район, ниже держит снег, выше растит парусность и площадь
покрытия; свес 600 держит воду от стены и при этом не съедает больше трети
трёхметрового отступа до границы — это правило, а не глазомер. Конёк идёт вдоль
дома: поперёк он дал бы фронтоны в 12,5 м. Чердак холодный, утепление 300 лежит
на перекрытии, а не по скатам — так дешевле и так не надо думать про пароизоляцию
по стропилам.

Навес веранды шире настила на 300 с трёх сторон: без свеса вода с него льётся
на доски. Площадь навеса считается по этой коробке, а не по настилу, — иначе
чертёж и смета разошлись бы на полтора метра. Стойки стоят по наружному краю
настила, и высота стойки берётся по низу навеса над ней, а не над краем свеса.

Три правила веранды написаны по следам трёх собственных промахов, и каждое
из них раньше считало не то. Проход под навесом мерился до плоскости ската —
а головой встречают прогон, и он висит на 200 ниже. Настил стоял на −150, то
есть прямо под полотном единственной входной двери была ступень; теперь −50,
водоотбойник. Свая уходила на 2500 от земли при промерзании 2500 — ровно
в границу, без коэффициента на неотапливаемое; теперь 3000, низ лопасти −3,300.

Отдельно — снеговой мешок. Правило «навес ниже подоконника» аттестовало как
норму окно, которое всю зиму стоит в сугробе: снег ложится НА навес и подпирает
стену выше самого навеса. Высота мешка считается от снегового района площадки
(`site.snow`), и подоконник обязан быть выше её на 100. Отсюда примыкание 3150,
а не 3000: оно попало в толщу перекрытия второго этажа — глухая зона, лучшее
место для планки, — и заодно дало проход под прогоном 2341.

Приямок люка — это коробка: три стенки, дно ниже уровня земли, борт выше
отмостки и решётка сверху, по которой ходят. Дно у него не ровное: лоток под
34° поднимается от порога люка наружу, и сброшенное с земли полено едет в люк
само. Ровное дно в списке координат и в выгрузке выглядит точно так же, а дрова
на нём остаются лежать — поэтому уклон лотка проверяется правилом, и правилом же
проверяется, что верхняя кромка лотка не упирается в крышку.

Порог наружной двери выше земли — это крыльцо, площадка и ступени, а не «дверь
в стене». На плане дверь выглядит одинаково с крыльцом и без него, поэтому
правило требует крыльцо для каждой двери с перепадом больше 150, кроме тех,
что выходят на настил веранды.

Дом стоит в земле, а не в пустоте: грунт площадки — тела groundGeom,
цоколь заглублён, наружу торчат 300 мм, и сваи с фундаментами труб уходят
в грунт. Без этого слоя модель читалась трёхэтажной коробкой на ходулях —
и так и уехала на страницу. Порог ворот выше земли — это пандус-съезд,
как порог двери — крыльцо. Слой «Участок» в смотрелке выключается,
чтобы подземную часть можно было разглядывать.

Всё, что вынесено за наружную стену, — приставные дымоходы, приямок, крыльцо —
собирается одним списком и разводится по фасаду. По отдельности каждый вынос
помещается; вместе они и составляют фасад, которого на плане этажа нет.
Отсюда правила: между выносами 400 (между приямком и крыльцом — 600, с крыльца
сходят вслепую), дымоход не встаёт перед окном, и от самого дальнего выноса
до границы участка остаётся 1200 на проход. Именно так нашлось наложение двери
гаража на люк для дров — на плане они были рядом и не пересекались ни одной
координатой.

## Участок

Участок 19 × 35 перестал быть числом в данных: у него есть тело, забор,
времянка и сети. Хранится по-прежнему решение — посадка дома (`setback`
до северо-западной границы и `red` до красной линии), времянка, септик,
точки ворот и угол врезки воды; всё остальное считает `src/plot.mjs`:
границы, панели забора, проезд, дорожки, коридоры сетей и их трассы.
Отступы по сторонам разные (3 / 5 / 8 / 17,5 м), и `plotMargins` раздаёт
их грунту, правилам и сетям из одного места.

Времянка стоит в дальнем углу СЗ-СВ — в ней живут, пока строится дом.
Это не наша коробка, а модель архитектора: каркасный дом 8,11 × 9,56
с открытой террасой 8,0 × 2,95 под общей двускатной кровлей 15°, на 24 сваях,
пять помещений, 43,2 м². Пришёл он файлом IFC из ArchiCAD, и из файла взято
решение, а не геометрия: габариты, толщины, уклон, свес, сетка свай,
перегородки и ведомость проёмов легли в `project.plot.temp` локальными
координатами, всё остальное считает `src/temp.mjs`. Отметки конька и карниза,
профиль ската, фронтоны, высота каждой стойки, ступени крыльца и площади —
вычисляются. Посадка на участке — это два числа, x и y, а не сорок.

Вклеивать присланный файл в наш было нельзя: 26 МБ, миллион треугольников,
и главное — вклеенная времянка выпала бы из правил, сметы и проверки модели,
став картинкой внутри выгрузки. Разбор чужого IFC — тот же web-ifc, что читает
страницу; обмер перепроверялся вторым проходом и нашёл четыре расхождения
в первом (ростверк 150, а не 180; подоконник 700, а не 675 — 675 это низ
выреза с четвертью; у террасы не ограждение, а боковые экраны из досок;
фронтоны обе до 3530, а «3820» — вырожденный плавник в чужой геометрии).

Отметка чистого пола времянки — не ноль дома: она на +550 при земле −300,
и это даёт 288 мм продуха под низом ростверка. Ступени крыльца считаются
от нашей земли, а не от той, что нарисована в чужом файле, — поэтому их
четыре, а не две.

Два места, где обмер сошёлся по верху и разошёлся по низу. Первое: `clear` —
высота в свету, то есть отметка на ВНУТРЕННЕЙ грани стены, а не на наружной.
Плоскость низа кровли, отсчитанная от наружной, уходит на толщину стены
по уклону — 245 · tg15° = 66 мм, — и вдоль обеих карнизных стен остаётся
клин пустоты на все 6120 мм. Поймать это по верху нельзя: толщина пирога
подбирается разницей, и конёк с карнизом сходятся с исходником до полуметра
миллиметра, пока низ висит на 66 выше. Сверяться надо тремя точками —
наружная грань, внутренняя, конёк.

Второе: щипцовая стена — не «стена плюс фронтон рядом». Пока фронтон был
отдельным элементом, вычитание проёма ставилось только на нижнюю коробку,
и верхние 611 мм витража сидели внутри глухого треугольника: в ведомости
3120, в ArchiCAD 2509. Ни счётчик проёмов, ни сверка их места в плане такого
не видят — вертикали они не касаются. Фронтон лежит в теле своей стены,
один проём режет оба, и проверка модели меряет верх заполнения против
верха щипцовой стены.

Ни одна стена под скатом не кончается одной отметкой: низ кровли зависит
от x и меняется и вдоль стены, и поперёк её толщины. Поэтому у каждой стены
и перегородки прямая часть до самой низкой точки над ней, а выше — клин
по скату, одним и тем же профилем для обеих ориентаций.

Времянка деревянная, и разрыв до каменного дома по норме 10 м. На этом
участке его нет: двор за домом 17,5 м, отступ от задней границы 3 м,
и деревянный дом 8,1 × 9,6 даёт максимум 4,9 м как есть и 6,4 м при повороте
на 90°. Разрыв принят отступлением — строение временное, на период стройки;
в данных это записано `role: "temporary"` и текстом `waiver`, а не молчанием.
Правило от этого не исчезло, а сменило вопрос: раз норму не выдержать, обязан
быть выдержан максимум, который участок вообще позволяет. Подвинули времянку
к дому, хотя место сзади было, — правило скажет.

Нормы постоянного жилого дома на времянку не переносятся: остекление
кухни-гостиной 15,0 м² на 18,2 м² пола (1/1,2 при нашем пределе 1/2 даже
для панорамного) — решение архитектора, и правила про это здесь нет.
Проверяется другое: сходятся ли помещения с перегородками, лежит ли проём
в своей стене, не упирается ли витраж в скат, дойти ли от входа до каждой
комнаты, проходит ли человек под карнизом, ниже ли промерзания свая,
есть ли продух, и не сходят ли с настила в пустоту с высоты 795.

Септик — станция биологической очистки, и тоже не по вкусу: зоны, где разом
выдержаны 5 м от обоих домов и отступ от границы, сжимаются на 19-метровом
фронте в полосу шириной в метр — классический септик с полем фильтрации
(8 м от жилья) сюда не встаёт геометрически. Станция стоит у уличного
забора: обслуживание и откачка ила — с улицы, машина на участок не
заезжает, и правило требует не дальше 5 м от красной линии. Очищенную
воду гонит напорный сброс в кювет — при такой посадке ему 1,7 м.
Самотёк набирает уклон в отметках самой трассы, и правило меряет вход
в станцию: отодвинулся септик — опустился вход, и глубже 2000 прогон
не пройдёт.

Вода приходит с угла ЮЗ-ЮВ: магистраль идёт фронтальной полосой до ввода
дома, тройником уходит в дом и продолжается западной полосой к времянке.
Западная полоса уже пяти метров, поэтому вдоль фундамента вода лежит
в футляре — футляры считаются автоматически: и на сближении, и на каждом
пересечении, где вода оказывается ниже канализации. Коридоры сетей
(`plotLanes`) выводятся из границ и септика, а не назначаются трубам
поодиночке; правило проверяет фактические трассы попарно — параллельные
сближения, зазоры на пересечениях, выход за границы и проход под зданиями.

Лист генплана собирается тем же способом, что планы этажей и кровля,
и его подписи проверяются тем же правилом на наложение. В выгрузке времянка
лежит в общем здании на отметке 0.000: вторым IfcBuilding она уже уезжала —
ArchiCAD раскладывает этажи по отметкам и молча её терял. Слоями её и
участок делают метки, а не типы: `plot.t*` — «Времянка», забор, ворота
и покрытия — «Участок»; перенос метки правится парой src/viewer.js +
bin/model.mjs, как и всё, что решает «видно ли это на экране». Список типов,
у которых вообще смотрят метку, — часть той же пары: времянка принесла в слой
сваи, ростверк, стойки и экраны, и типа, забытого в одном из двух файлов,
хватит, чтобы половина её пропала с экрана, оставшись в файле. Смета
получила раздел «Участок и времянка» из тех же геометрий.

## Комплект прораба

Ревизия глазами прораба нашла не только отсутствующие листы, но и два дефекта
самого решения — оба чинились в данных и стали правилами. Стоки цоколя лежат
на метр ниже лотка выпуска, самотёком им некуда деться: в душевой-постирочной
стоит КНУ, и правило требует её на каждом уровне, где слив ниже выпуска.
Смета копала котлован до подбетонки (−3,40), а модель клала песчаную
подготовку до −3,70: дно котлована теперь считает foundationBottom — один
источник на смету, выгрузку и лист разреза.

Канализация внутри дома была вся из ПП 50 — унитазы переведены на 110-ю,
стояк 110 с фановым выходом над скатом (+300) посчитан в ведомость, вырез
в кровле и труба — в модель. Перемычки перестали быть строкой «61,5 п.м»:
ведомость раскладывает их по толщинам стен, широкие проёмы (ворота,
панорамное) — монолитные участки по расчёту, проёмы монолитного цоколя —
обрамление в КЖ; правило не пускает проём шире 3200 ни в какую перемычку.

Листы: четыре фасада (оси проёмов и отметка низа каждого окна — то, что
правило 35 выравнивало вслепую) и разрез 1-1 по лестничной шахте (дно
котлована, пирог, толщины перекрытий, марши, ферма, веранда). Оба строятся
той же машинерией, что кровля и генплан, и их подписи проверяются тем же
правилом на наложение — по каждому листу отдельно. На планах этажей у каждой
наружной стены появилась цепочка привязок проёмов: простенок — проём —
простенок; 38 проёмов не входили ни в одну цепочку вовсе.

Спецификации на странице: ведомость заполнений по маркам (ОК/ДН/ДВ/В/Л
с отметками низа и количеством), ведомость перемычек, гильзы и закладные
в монолите (по точкам входа фактических трасс — их кладут в опалубку до
заливки). Армирование, антисейсмические пояса (площадка 8 баллов) и узлы
фермы — раздел «Передаётся конструктору»: это расчётная работа, и выдавать
её «по опыту» нельзя; геология не выполнена и записана допущением в задании.

## Что нельзя менять без разговора

Задание живёт в `data/brief.json` — там же, где геометрия, и оттуда же попадает
на страницу. Читать перед правками, дублировать в других файлах не надо.
Коротко: габарит 8000 × 12500 и ориентация воротами на юго-запад, гараж на две
машины, две спальни с гардеробной, спальные — в дальнем от дороги конце, вход
только с веранды, мокрые помещения трёх уровней на одном стояке, погреб не нужен.

Все семь пунктов задания проверяются против `brief.json` автоматически: габарит,
глубина гаража, две машины, гардеробная, вход только с веранды, отсутствие погреба,
спальня хозяев в дальнем конце. Разойтись молча они не могут.

Вход с веранды и вход из гаража идут через тамбур — это тоже правило, а не
пожелание: помещение с меткой `lock` обязано стоять между улицей и домом.

## Что решено и почему

Гостевая спальня стоит у уличного фасада. Это осознанно: в дальнем от дороги конце
2930 мм глубины, туда влезает одна спальня с гардеробной. Пункт задания
сформулирован под это — «спальня хозяев в дальнем конце», и проверяется по роли
`role: "master"`, а не по площади.

Лестница — двухмаршевая с поворотом на 180°, в шахте 3400 × 2200 у западной
наружной стены: два марша по 1050 рядом, промежуточная площадка в западном
конце. Шахта стоит именно у стены, а не посреди этажа: марш опирается на
несущую стену, а не на перегородку 120, и середина плана остаётся целой.
Площадка не задаётся числом, а остаётся от шахты за маршем: длина марша —
ступени на проступь, и оба марша прижаты к восточному торцу, с которого
входят и на который выходят. `landing` в данных — заявленный минимум, правило
требует, чтобы остаток был не меньше него и не уже марша. Свободного пола
внутри шахты нет, поэтому вход и выход — только с восточного торца, через
открытый проём 2000 в прихожую (на втором этаже — в холл). Пол прихожей и есть
площадка перед маршем: 1630 мм в глубину — больше ширины марша.

Отсюда правило «дверь не открывается на марш»: перед полотном нужен ровный пол.
Открытый проём (`kind: "pass"`) исключён намеренно — там нет полотна, и низ марша
начинается сразу за ним. Ось лестницы, стояк и мокрые помещения держатся общими
координатами: шахта x 400…3800, несущая стена 250 по x 3800…4050,
служебная полоса y 6850…9050 — на всех трёх уровнях одинаково. На первом
этаже восточная треть полосы отдана тамбуру и санузлу, в цоколе и на втором
она целиком прихожая и холл. Стояк ушёл из служебной полосы в северо-восточный угол
(x 7300…7600, y 9170…9570), мокрые помещения собрались вокруг него.

Плата за перенос лестницы к стене известна и принята: жилая площадь
87,8 → 72,6 м², спальня хозяев 14,9 → 10,1 м², кухня-гостиная 21,1 → 16,3 м²,
зона отдыха 14,9 → 9,3 м², гардеробная 5,9 → 4,4 м²; прихожая и холл выросли
3,5 → 7,8 м² на уровень, а прямая дверь из гостиной на веранду исчезла —
на веранду выходят из прихожей.

Цоколь собран вокруг двух вещей, которых не видно в списке помещений.
Первая — дрова. Котельная стоит в северо-западном углу, за ней дровяник,
в его наружной стене люк 900 × 800 с приямком: дрова падают прямо к котлу,
а не едут через прихожую и лестницу. Дымоходы обоих приборов, котла и печи
сауны, вынесены на ту же северо-западную сторону. Вторая — стояк: он один
на три уровня, поэтому душевая-постирочная не двигается.

Из этого следует и весь остальной цоколь. Западная полоса техническая:
котельная, дровяник, сауна — одна за другой, и в котельную входят через
дровяник, а не из комнаты. Вся восточная половина от улицы до служебной
полосы отдана зоне отдыха, 22,0 м² одним объёмом: она же предбанник сауны
и она же то, ради чего цоколь копали. Мастерская и кладовая ушли в дальний
конец к постирочной — там им и место: 8,5 и 6,6 м², вход из прихожей через
кладовую. Жилая площадь дома от этого 76,3 → 87,4 м².

Вход в дом — через тамбур 1800 × 2200 в восточном углу служебной полосы:
в него ведут и дверь с веранды, и дверь из гаража, из него — дверь в прихожую.
Санузел открывается из кухни-гостиной, а не из тамбура: в тамбуре холодно
и он проходной. Правило держит это с двух сторон: из гаража нельзя открыть
дверь в помещение без метки `lock`, и входная дверь обязана вести в такое же.
Плата — прихожая 3,6 м² вместо 7,8: тамбур отрезал от полосы восточную треть.
Санузел стоит в северо-восточном углу тем же прямоугольником 1800 × 2930, что
душевая в цоколе и санузел на втором: три мокрых помещения совпадают по стенам,
и стояк проходит сквозь них по одной оси.

Окна в гараже нет: оно ничего там не освещает, а мостик холода делает.
Вместо него дверь во двор на северо-западной стороне, рядом с люком для дров, —
дрова, инструмент и мусор ходят вдоль дома, а не через дом.

Второй этаж переигран дважды, и обе правки об одном — о том, что шахта
лестницы отрезает западную половину этажа от холла. Сначала поперечный
коридор 7200 × 1000 был убран, а холл продлён на север: обе комнаты стали
открываться прямо в него. Потом гостевая 21,9 м² оказалась слишком большой
для одной комнаты, её разделили надвое — и коридор вернулся, но другой:
не поперёк этажа, а вдоль перегородки, 900 × 6200, от улицы до холла,
с окном в торце. Он обслуживает обе комнаты и стоит 5,6 м².

Цена деления известна: комнаты вышли по 7,5 и 7,7 м², кровати в них
полутораспальные 1200 × 2000 — двуспальная требует 700 прохода с каждой
стороны и в 2510 мм ширины не помещается. Кабинет уменьшен 17,3 → 14,2 м²,
освободившееся отдано холлу: 13,0 → 16,1 м².

## Окна

Окна — не «сколько влезет». Здесь их держат четыре правила, и все четыре
проверяются:

* **Света не меньше 1/8 пола и не больше 1/4,5.** Нижняя граница — норма
  освещённости, верхняя — расчётная зима −33 °C: лишнее стекло это не «светло»,
  а дыра в стене. До правки в кухне-гостиной стояло 6,3 м² остекления на 16 м²
  пола — 1/2,6, вдвое выше всякого предела, и никто этого не видел.
* **Верх всех окон этажа — на одной отметке (2400).** Разнобой по верху виден
  на фасаде сразу, а в списке координат — никогда. Подоконник при этом гуляет:
  700 в столовой, 1400 над кухонным фронтом, 1600 в санузле, 400 в спальне.
* **Панорамное окно помечается `pano`.** Иначе «низкое окно» появляется
  случайно. Помеченному разрешено до половины пола вместо 1/4,5 — это решение,
  а не оплошность.
* **Под окном с подоконником ниже 700 радиатор не встаёт** — он упирается
  в стекло. Там ставится внутрипольный конвектор, и генератор точек знает об
  этом сам. Обратное тоже правило: конвектор под обычным окном — деньги на ветер.

Пятое правило — оси. Верх окон этажа держит одну отметку давно, а по
горизонтали окна стояли кто где: ось окна второго этажа в 250–350 мм от оси
ворот или двери под ним с земли читается как ошибка построения. Теперь ось
либо совпадает с осью проёма другого этажа, либо разведена не меньше 600;
парные ворота стоят с равными полями от углов; окно, вставшее почти по центру
своего помещения, ставится в центр точно — если оно не держит ось фасада.
Так съехали с мест девять окон из четырнадцати надземных.

Сторон четыре, и они не равны: юго-восток солнечный, юго-запад уличный,
северо-восток смотрит в глубину участка, северо-запад — в трёх метрах от
границы. Поэтому панорамное окно спальни хозяев 2400 × 2000 выходит на
северо-восток, в сад; на северо-западе окон меньше и они мельче; санузел
получает узкое окно под потолок, а не «как у всех».

## Личные данные

Адрес и любые данные владельца в репозиторий не попадают: он публичный,
и с него собирается сайт. Площадка описывается только числами — климат,
сейсмика, габарит участка, ориентация.

## Что попадает в историю

Собранное — в `out/` и `site/`, оба игнорируются. В корне репозитория артефактов
не бывает: всё, что там появилось, — чей-то временный файл. Поэтому `git add -A`
без взгляда на `git status` однажды затащит в историю чужие кропы. Смотреть,
что коммитишь.

## Стиль чертежа

Двери — просто проёмы, без дуг открывания. Размеры в миллиметрах.
Никаких ссылок на предыдущие версии в самих файлах.
